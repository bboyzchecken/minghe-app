## 3. สามเรื่องที่ต้องเคาะก่อนเขียนโค้ด

### 3.1 หนึ่งรหัสต่อคน หรือหนึ่งรหัสต่อกลุ่ม ⭐ ตัวชี้ขาดทั้งดีไซน์

ตัวอย่างที่ให้มา `G1S12026` อ่านได้ว่า Group1 / Set1 / 2026 = **รหัสกลุ่ม**
แต่โจทย์ "ย้อนดูว่า*เขา*กดอะไรไปบ้าง" ต้องแยกคนออกจากกันได้

> **เสนอ: ออกเป็นรหัสรายคนที่มีคำนำหน้าเป็นกลุ่ม** — `G1S1-2026-07` (คนที่ 7 ของกลุ่ม G1S1)
> แอดมินยังดูรวมทั้งกลุ่มได้จาก prefix และดูรายคนได้จากรหัสเต็ม ไม่ต้องเลือกอย่างใดอย่างหนึ่ง

ถ้ายืนยันใช้รหัสกลุ่มร่วมกันจริง ๆ ระบบยังแยกคนได้ด้วย `anon_id` แต่จะแยกได้แค่ "เบราว์เซอร์" ไม่ใช่ "คน" — คนเดียวเปิดสองเครื่องจะกลายเป็นสองคน และสองคนใช้เครื่องเดียวกันจะกลายเป็นคนเดียว **ต้องยอมรับข้อจำกัดนี้ก่อน**

### 3.2 รหัสมาก่อนหรือหลังล็อกอิน

> **เสนอ: มาก่อน และผูกตั้งแต่หน้าแรก**
> รับได้ 2 ทาง — ลิงก์ `https://…/?code=G1S1-2026-07` (แจกทางไลน์ กดแล้วเข้าเลย) หรือกรอกเองที่หน้า `/access`
> เก็บใน `localStorage` แล้วแนบไปกับ **ทุก** event ตั้งแต่วินาทีแรก

ถ้าให้กรอกตอนจะเปิดรายงาน จะไม่รู้เลยว่าคนที่หายไปกลางทางคือใคร ซึ่งเป็นข้อมูลที่มีค่าที่สุดของ UAT

### 3.3 Google Analytics ตอบโจทย์ได้แค่ครึ่งเดียว — ต้องรู้ก่อนตัดสินใจ

GA4 เก่งเรื่อง **ภาพรวม**: กรวย จำนวนคน เวลาเฉลี่ยต่อหน้า เทียบกลุ่ม
GA4 **ตอบไม่ได้ดี** เรื่อง "เปิดดูว่าคนนี้กดอะไรไปบ้างเรียงตามเวลา" — รายงานรายคนไม่มีใน UI มาตรฐาน ต้องต่อ BigQuery export และมี threshold ซ่อนข้อมูลกลุ่มเล็ก ซึ่งกลุ่มผู้ทดสอบ UAT เล็กเกินกว่าจะรอด

> **เสนอ: เขียนสองที่ (dual-write)**
> - **ฐานข้อมูลตัวเอง = ต้นทางความจริง** → หน้าแอดมิน "ย้อนดูรายคน" อ่านจากตรงนี้
> - **GA4 = แดชบอร์ดภาพรวม** ส่ง `access_code` เป็น custom dimension เอาไว้เทียบกลุ่ม
>
> โค้ดฝั่งหน้าเว็บเรียกฟังก์ชันเดียว แล้วให้มันแตกไปสองทาง — ไม่ได้เขียนสองรอบ

## 4. โครงสร้างข้อมูล

### 4.1 ตารางใหม่ 2 ตาราง

```go
// AccessCode — รหัสเข้าใช้ช่วงทดลอง ใช้แทนการชำระเงิน
type AccessCode struct {
    ID    uint   `gorm:"primarykey"`
    Code  string `gorm:"uniqueIndex;size:32;not null"` // G1S1-2026-07 — เก็บเป็นตัวพิมพ์ใหญ่เสมอ
    Group string `gorm:"index;size:16"`                // G1S1 — ไว้ดูรวมทั้งกลุ่ม

    Label   string // "คุณเอ ฝ่าย HR บริษัท ก" — ให้แอดมินรู้ว่าแจกใคร
    Product string `gorm:"size:16;default:any"`
    Depth   string `gorm:"size:16"`

    MaxUses   int `gorm:"default:1"` // 1 = รายคน · >1 = รหัสกลุ่ม
    UsedCount int

    Status     string `gorm:"size:16;default:active;index"` // active | exhausted | revoked
    ExpiresAt  *time.Time
    IssuedByID uint
    CreatedAt  time.Time
}

// AccessCodeRedemption — หนึ่งแถวต่อหนึ่ง "การเริ่มใช้" ของรหัส
// รหัสกลุ่มหนึ่งรหัสจะมีหลายแถว = แยกผู้ทดสอบออกจากกันได้
type AccessCodeRedemption struct {
    ID         uint   `gorm:"primarykey"`
    CodeID     uint   `gorm:"index;not null"`
    AnonID     string `gorm:"size:64;index"` // ตัวระบุเบราว์เซอร์ ตั้งแต่ก่อนล็อกอิน
    UserID     *uint  `gorm:"index"`         // เติมทีหลังเมื่อล็อกอิน
    OrderID    *uint  `gorm:"index"`         // ออเดอร์ที่รหัสนี้ปลดล็อกให้
    FirstAt    time.Time
    LastSeenAt time.Time
}
```

### 4.2 ขยาย `FunnelEvent` เดิม — เพิ่ม 5 คอลัมน์

```go
type FunnelEvent struct {
    // ...ของเดิม: ID, AnonID, UserID, Product, Step, StepIndex, CreatedAt

    Code    string `gorm:"size:32;index"` // ⭐ รหัสที่ผูกอยู่ตอนเกิด event
    Kind    string `gorm:"size:16;index"` // view | click | leave | error
    Path    string `gorm:"size:191"`      // /employer/new
    Target  string `gorm:"size:64"`       // ชื่อปุ่ม เช่น btn_next · btn_back · card_premium
    DwellMs int                           // ⭐ อยู่หน้า/ขั้นนี้กี่มิลลิวินาที
}
```

### 4.3 ⚠️ ต้องแก้ตรรกะเดิมข้อหนึ่ง

[`track.ts:32`](../apps/app/lib/track.ts#L32) มี `const sent = new Set()` ที่ **กันส่งซ้ำในเซสชันเดียว** — ตั้งใจไว้ให้นับ funnel ไม่เบิ้ล
แต่ตรรกะนี้จะทำให้ **ตอบคำถาม "ใช้เวลาไปกับอะไร" ไม่ได้เลย** เพราะคนที่กดย้อนกลับไปกลับมา 5 รอบจะถูกบันทึกครั้งเดียว

> วิธีแก้: เก็บ dedupe ไว้เฉพาะ `kind: "view"` ที่ใช้นับกรวย ส่วน `click` และ `leave` ส่งทุกครั้ง
> การนับกรวยฝั่งแอดมินใช้ `COUNT(DISTINCT anon_id)` อยู่แล้ว จึงไม่พังแม้ส่งซ้ำ

## 6. 🔴 ด่าน compliance ที่ข้ามไม่ได้

[`lib/legal/cookies.ts`](../apps/app/lib/legal/cookies.ts) เขียนประกาศไว้เองว่า:

> *"ไม่ได้ใช้คุกกี้ติดตามและไม่มีเครื่องมือวิเคราะห์พฤติกรรมของบุคคลที่สาม จึงไม่ต้องมีแบนเนอร์ขอความยินยอม"*
> *"⚠️ ถ้าวันไหนติดตั้ง Google Analytics … ต้องกลับมาแก้เอกสารฉบับนี้และเพิ่มแบนเนอร์ขอความยินยอมก่อนใช้งานจริง"*

**วินาทีที่ติด GA คือวินาทีที่ประโยคนี้กลายเป็นเท็จ** — GA จึงปล่อยไม่ได้จนกว่าจะทำครบ 3 ข้อ:

- [ ] แก้ `cookies.ts` — เขียนตามจริงว่าใช้ GA4 เก็บอะไร เก็บนานเท่าไร ส่งไปที่ไหน
- [ ] เพิ่มแบนเนอร์ขอความยินยอม — ปฏิเสธได้ และปฏิเสธแล้ว **ต้องไม่โหลด gtag เลย**
- [ ] แก้ `privacy.ts` เพิ่ม GA เป็นผู้ประมวลผลข้อมูลภายนอก

ส่วนการแทร็กของเราเอง (first-party ไม่มีคุกกี้บุคคลที่สาม เก็บแค่ชื่อขั้นกับเวลา) ทำได้ทันทีโดยไม่ต้องรอแบนเนอร์ — **นี่คือเหตุผลที่ P0 ทำได้ก่อน GA**

**อีกจุดที่ต้องแก้พร้อมกัน**: หน้าราคายังพูดเรื่องเก็บเงิน ถ้ารอบนี้ไม่เก็บเงินจริงต้องเขียนให้ตรง — ประเด็นเดียวกับที่ S3 เพิ่งแก้เรื่อง "ซินแสตรวจทาน" ([`legal/refund.ts`](../apps/app/lib/legal/refund.ts) และ [`terms.ts`](../apps/app/lib/legal/terms.ts) ต้องไล่ดูด้วย)
