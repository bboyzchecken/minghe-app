### กลุ่ม A — Legal & Payment Gateway (บล็อกการขายจริง)

#### F-01 · เอกสารกฎหมาย 4 ฉบับ เพื่อยื่นขอ payment gateway
- **ที่มา**: หน้า 2 (Next step), หน้า 12 ข้อ 1
- **ต้นฉบับ**: *"ทำ privacy notice, cookie policy, เงื่อนไขการใช้งาน, นโยบายคืนเงินและการขอลบบัญชี เพื่อทำ payment gateway"*
- **ประเภท**: ⚖️ Legal + 🔧 Function (ต้องมีหน้าเว็บจริง + ลิงก์ใน footer)
- **ยาก-ง่าย**: **M** (โครงหน้าเว็บ = S / เนื้อหากฎหมาย = ต้องมีคนตรวจ)
- **ความพร้อม**: 🟡 — โครงและกติกาชัดแล้ว เหลือ 3 ข้อเท็จจริงที่ต้องได้จากเจ้าของธุรกิจ
- **สถานะปัจจุบัน**: `apps/app` มีหน้า stub `/legal/{terms,privacy,refund,cookies}` จองไว้แล้ว (Wave 1) · `apps/web` มี privacy/terms ฉบับเก่าใช้เป็นตั้งต้นได้
- **ตัดสินแล้ว**
  - Gateway = **GB Prime Pay** → ต้องมีครบ 4 ฉบับ + แสดงข้อมูลผู้ขายและราคาเป็นบาทชัดเจน
  - **Retention**: เก็บตราบเท่าที่บัญชียังใช้งาน · ลบข้อมูลส่วนบุคคลภายใน **90 วัน** หลังผู้ใช้ขอลบบัญชี · เอกสารธุรกรรมเก็บ **5 ปี** ตามกฎหมายบัญชี
  - **ช่องทาง PDPA**: `info@minghe.work` อย่างเดียว — เขียนว่า "ช่องทางติดต่อเรื่องข้อมูลส่วนบุคคล" ยังไม่ใช้คำว่า DPO จนกว่าจะแต่งตั้งจริง
  - **Cookie**: ใช้เฉพาะคุกกี้จำเป็น (session/login) → **ไม่ต้องมี consent banner** เขียน cookie policy อธิบายให้ครบพอ ⚠️ ถ้าวันไหนติด GA/Pixel ต้องกลับมาเพิ่ม banner
- **ยังรอ 🔑**: ข้อมูลนิติบุคคล (B1) · เงื่อนไขคืนเงินจริง (B2) · ผู้ตรวจเอกสาร (B3) → ดู [ชีทคำถามค้าง](uat-2026-08-01-ask-ajarn-may.md)
- **หมายเหตุ**: ข้อความกฎหมายผมร่างให้ได้ แต่ควรมีคนตรวจก่อนใช้จริง — ไม่ควร publish ร่างที่ AI เขียนโดยไม่มีคนตรวจ

### กลุ่ม B — Auth & User Flow

#### F-02 · ล็อกอินด้วยอีเมล + Google สำหรับบุคคลทั่วไป
- **ที่มา**: หน้า 3
- **ต้นฉบับ**: *"อยากให้ล็อกอินผ่านอีเมล คนทั่วไปและกูเกิล"*
- **ประเภท**: 🔧 Function
- **ยาก-ง่าย**: **M** (auth ฝั่ง Go มีโครงแล้ว) → **+S** สำหรับ Google OAuth
- **ความพร้อม**: 🟢 — เริ่มได้ทันที (ส่วน Google รอแค่ Client ID ไม่บล็อกงานอีเมล)
- **ตัดสินแล้ว**
  - **Go API ถือ auth ทั้งหมด** — ออก session/JWT เอง · หน้าเว็บไม่มี auth ของตัวเอง · ไม่ใช้ NextAuth (กันปัญหา auth สองชุดที่ต้อง sync กัน)
  - **Google OAuth ทำใน Go ทั้ง flow** — กดปุ่ม → redirect ไป Go → Go คุยกับ Google เอง → ออก session · Client Secret อยู่ฝั่ง server ที่เดียว
  - **สมัครด้วยอีเมลอะไรก็ได้** — ไม่บังคับอีเมลบริษัท (บางบริษัทไม่มีเมล business) แต่คนทำงานส่วนใหญ่มี Google ส่วนตัวอยู่แล้ว จึงเปิดทั้งสองทาง
  - **ต้องยืนยันอีเมลก่อนใช้งาน** — เพราะรายงานส่งทางอีเมล พิมพ์ผิด = จ่ายแล้วไม่ได้ของ → ต้องเลือกผู้ให้บริการส่งอีเมล (Resend / SES / SendGrid)
  - **บัญชีเดียวสลับสองโหมด** องค์กร ↔ คนหางาน · ข้อมูลส่วนตัวกับข้อมูลองค์กรแยกกันชัดเจนใต้บัญชีเดียว
- **ยังรอ 🔑**: Google Cloud project + Client ID (B4) — ระหว่างนี้ปุ่ม Google แสดงแต่กดไม่ได้ ผ่าน flag `NEXT_PUBLIC_GOOGLE_LOGIN_ENABLED` ที่มีอยู่แล้ว

#### F-03 · First-time trial — ให้เล่นโฟลว์ได้ก่อน แต่บังคับ login/สมัคร ตอนชำระเงิน
